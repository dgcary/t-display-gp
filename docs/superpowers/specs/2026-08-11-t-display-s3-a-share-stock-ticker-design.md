# T-Display-S3 A股实时行情终端 — 设计规格

日期：2026-08-11
GitHub 仓库：`dgcary/t-display-gp`
状态：用户已批准（2026-08-11）

## 1. 项目目标

在 LILYGO T-Display-S3 上实现一个可长期使用的 A 股实时行情终端。设备通过 Wi-Fi 联网，每 3–5 秒刷新所选股票行情，支持 3–5 只股票、实体按键切换、当日分时图、手机 Web 配网与股票池配置。

项目优先复用成熟开源方案，不从零实现通用能力。主干参考 Zaitronics `esp32-cyd-stock-ticker` 的 Arduino/C++、WiFiManager、Web 配置和配置持久化设计；参考 `dcluomax/stock-ticker-esp32c6` 的分时图、交易时段状态和移动端配置交互。硬件显示与按键层适配 T-Display-S3。

## 2. MVP 范围

### 2.1 支持的市场与股票池

- 仅支持 A 股。
- 同时配置 3–5 只股票。
- 用户通过手机 Web 配置页修改股票代码和显示名称。
- 股票代码内部使用统一规范格式，数据 Provider 负责转换成各行情源所需格式。

### 2.2 行情数据

单股详情页必须显示：

- 股票名称与代码
- 当前价
- 涨跌额
- 涨跌幅
- 今开
- 最高
- 最低
- 昨收
- 成交量
- 成交额
- 当日分时走势图
- 当前市场状态：交易中 / 午间休市 / 已收盘 / 非交易日 / 数据异常

### 2.3 刷新策略

- 连续竞价交易时段：默认每 5 秒刷新一次实时快照；允许后续在 Web 配置页调整到 3–5 秒范围。
- 分时数据不要求与快照同频全量刷新；采用独立刷新节奏，默认每 30–60 秒拉取一次分钟级分时数据，以降低接口压力和内存抖动。
- 午间休市：停止高频刷新，保留最后行情；以低频检查方式等待下午开盘。
- 收盘后：显示“已收盘”，保留当天最后行情和完整分时图。
- 下一交易日进入交易时段后自动恢复实时刷新。
- 非交易日保留最近一个交易日数据，并显示非交易状态。

## 3. 用户交互

### 3.1 实体按键

V1 使用 T-Display-S3 板载实体按键，不增加外置按键。

- 按键 1：上一只股票
- 按键 2：下一只股票
- 按键需去抖。
- V1 不定义长按快捷功能，避免扩大范围；长按功能保留为后续扩展点。

### 3.2 首次配网

设备没有有效 Wi-Fi 配置时：

1. 自动进入 AP 配网模式。
2. 手机连接设备热点。
3. Captive Portal 自动打开配置页面；若系统未自动弹出，可通过固定网关地址访问。
4. 用户选择 Wi-Fi 并输入密码。
5. 同一配置流程中允许设置 3–5 只股票。
6. 保存后设备重启并连接目标 Wi-Fi。

### 3.3 日常 Web 配置

设备正常联网后提供局域网 Web 设置页，至少支持：

- 查看当前连接状态
- 修改 Wi-Fi
- 修改股票池
- 调整行情刷新间隔（限定 3–5 秒）
- 查看设备 IP
- 保存并应用配置

V1 不做账号系统、云端配置、远程公网管理。

## 4. 显示设计约束

硬件屏幕为 170×320，设计目标是“单股详情优先”，不是在一屏同时展示全部股票。

单股页建议采用纵向布局：

1. 顶部：股票名称、代码、市场状态
2. 主价格区：当前价 + 涨跌额 + 涨跌幅，大字号
3. 指标区：今开 / 最高 / 最低 / 昨收
4. 成交区：成交量 / 成交额
5. 下半区：当日分时图
6. 底部：当前序号，例如 `2/5`，以及 Wi-Fi / 数据状态的轻量提示

涨跌颜色遵循 A 股习惯：涨红、跌绿、平盘使用中性色。分时图颜色与价格状态区分开，避免信息混淆。

V1 优先保证可读性和局部刷新稳定，不追求动画特效。

## 5. 软件架构

采用 PlatformIO + Arduino/C++。

核心模块边界：

### 5.1 `DeviceLayer`

负责：

- T-Display-S3 初始化
- TFT_eSPI 显示驱动
- 背光
- 板载按键
- Wi-Fi 状态
- NVS/Preferences 配置存储

禁止包含股票业务逻辑。

### 5.2 `ConfigManager`

负责：

- Wi-Fi 相关配置
- 股票池配置
- 刷新周期
- 配置校验
- 配置持久化与版本迁移

股票池采用结构化配置，例如：

```text
StockItem {
  symbol
  display_name
  market
  enabled
}
```

### 5.3 `ProvisioningService`

负责：

- AP 模式
- Captive Portal
- 首次配网
- 日常 Web 配置页
- 配置提交与重启/热应用

优先复用 WiFiManager 或主干项目已有实现，避免自研 DNS Captive Portal。

### 5.4 `QuoteProvider` 接口

行情源必须可替换，业务层不能直接依赖某个网站字段。

接口至少提供：

```text
getQuote(symbol) -> QuoteSnapshot
getIntraday(symbol) -> IntradaySeries
healthCheck() -> ProviderStatus
```

`QuoteSnapshot` 统一字段：

- symbol
- name
- last
- change
- change_percent
- open
- high
- low
- prev_close
- volume
- amount
- timestamp
- market_status

`IntradaySeries` 至少包含时间点和价格；若数据源可提供均价/成交量，内部结构允许保留，但 V1 UI 不强制展示。

### 5.5 Provider 实现

V1 计划：

- Primary：东方财富 Provider
- Fallback：腾讯 Provider

约束：

- 免费公开接口优先。
- 这些接口属于非正式/可能变更的数据源，因此解析层必须隔离。
- Provider 失败不能直接导致 UI 崩溃。
- 若主 Provider 连续失败达到阈值，自动尝试备用 Provider。
- Provider 切换对 UI 和业务层透明。

分时数据若备用源能力不足，可在 V1 中允许“实时快照已切备用源，但分时图暂时保留最后成功数据”的降级模式。

### 5.6 `StockController`

负责：

- 当前股票索引
- 按键切换
- 调度行情刷新
- 调度分时刷新
- 交易状态机
- 缓存最后成功行情
- Provider 主备切换

不直接负责绘图。

### 5.7 `StockScreen`

负责：

- 将统一行情模型渲染到 170×320 屏幕
- 数值格式化
- 涨跌颜色
- 分时图绘制
- 局部刷新
- 数据异常/断网状态提示

UI 不直接发网络请求。

## 6. 数据流

正常交易时：

```text
Timer / Scheduler
      ↓
StockController
      ↓
QuoteProvider
      ↓
HTTP(S) request
      ↓
Provider parser
      ↓
QuoteSnapshot / IntradaySeries
      ↓
StockController cache
      ↓
StockScreen render
```

用户按键切换时：

```text
Button → StockController → 切换 currentIndex
                         ↓
                 立即渲染缓存
                         ↓
            若缓存过期则触发行情刷新
```

这样切换股票时不会等待网络请求后才出现画面。

## 7. 交易状态机

V1 内置中国大陆 A 股常规交易时间判断，同时以行情返回状态作为辅助。

状态：

- `PRE_OPEN`
- `TRADING_AM`
- `LUNCH_BREAK`
- `TRADING_PM`
- `CLOSED`
- `NON_TRADING_DAY`
- `UNKNOWN`

设备不能仅凭本地日期永久判断交易日，因为法定节假日和调休会变化。V1 策略：时间表决定刷新节奏，行情接口实际是否返回当日新数据决定最终显示状态；不在固件中维护复杂年度交易日历。

## 8. 网络与错误处理

### 8.1 Wi-Fi 断开

- 保留最后成功行情。
- UI 显示离线状态。
- 后台自动重连。
- 不因网络断开阻塞按键和界面。

### 8.2 HTTP/API 错误

- 设置合理连接与读取超时。
- 单次失败不切 Provider。
- 连续失败达到阈值后尝试备用 Provider。
- 恢复后允许重新回到 Primary，但需避免每次请求来回抖动。

### 8.3 JSON/响应格式变化

- Provider parser 对关键字段做存在性、类型和范围校验。
- 解析异常按 Provider 失败处理。
- 业务层仅接收经过校验的统一模型。

### 8.4 时间同步

- 联网后通过 NTP 同步时间。
- 未完成时间同步前，不使用本地时间做严格交易状态判断；界面可显示“同步时间中”。

## 9. 性能与资源策略

T-Display-S3 资源足以支撑该应用，但仍遵循嵌入式约束：

- 避免每 5 秒整屏全刷，优先局部重绘。
- 分时数据使用定长数组或可控容量容器。
- HTTP 响应限制最大长度，避免异常响应占满堆。
- JSON 文档按实际字段估算容量，不无限制动态扩张。
- 图片/字体资源放 Flash，必要时使用 PSRAM 保存较大的临时缓冲。
- V1 不加入复杂动画、图片背景、云同步。

## 11. 测试策略

### 11.1 主机侧单元测试

尽量将与 Arduino 硬件无关的逻辑设计为纯 C++，便于测试：

- 股票代码规范化
- Provider 响应解析
- 数值格式化
- 涨跌状态判断
- 配置校验
- 交易状态机
- Provider failover 逻辑

### 11.2 设备侧测试

必须覆盖：

- 首次无配置启动
- Captive Portal 配网
- Wi-Fi 凭据错误
- Web 修改股票池
- 3–5 只股票按键切换
- 行情正常刷新
- 主 Provider 失败
- Wi-Fi 中断与恢复
- 午间休市
- 收盘状态
- 重启后配置保留
- 分时图完整性
- 中文股票名显示

### 11.3 验收标准

MVP 完成需满足：

1. 空白设备可仅通过手机完成首次 Wi-Fi + 股票池配置。
2. 设备连接网络后能稳定展示至少 3 只 A 股。
3. 实时价格在交易时段按 3–5 秒刷新。
4. 两个实体按键可可靠切换股票。
5. 单股页包含需求定义的全部行情字段和当日分时图。
6. 收盘后保留最后行情并明确显示“已收盘”。
7. 次日交易开始后无需人工操作即可恢复刷新。
8. 主行情源异常时，快照行情可自动尝试备用 Provider。
9. 网络临时断开不会导致设备死机，恢复后自动继续。
10. 重启后 Wi-Fi 与股票池配置仍存在。
